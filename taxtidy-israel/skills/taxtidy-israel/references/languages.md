# Language and returning cases

Default to Hebrew; follow a returning user's requested language. Keep official Hebrew form names and public entry labels beside translations. The utility returns structured facts and a saved preference, not a translation engine. Compose the actual response in the preferred language. Do not claim a mailbox exists because an account is mentioned; discover capability and authorization first. With no authorized mailbox, explain manual retrieval without asking the user to reconnect merely to continue.

Read the private checkpoint and newly supplied evidence before asking consequential questions. Use `resume --input` for reviewed new evidence and `--language` for the requested preference. Use `summary`/`resume` projections, never cached artifact amounts. A missing Form106 presence flag can resolve while its amounts still conflict. A conflicting source suppresses the old estimate in every language. Ask payroll for the exact correction/reconciliation rather than requesting the document again as if absent. If a result has missing/legacy freshness metadata, retain its quarantined history and recalculate before showing a current amount.

Always end with a year table: estimated amount with year/ILS/direction or exact blocker; what was actually filed and its evidence; what can finish now; precise next document/institution/action; the public service label and its limited meaning. Render `next_control_he` and `control_scope` in the actual response, not only a tool result. An uploaded file is not a return, an accepted attachment is not filing, and a signed calculation is not an acknowledgment. Ask only questions changing the result, route or next action. When evidence suffices, finish the supported calculation without repeating intake questions. For an unsupported year, continue collection/reconciliation without promising that importing evidence enables local recalculation.

Language examples for the same workflow (not proof that trials passed):

- Hebrew: “קראתי את התיק השמור. התקבל טופס 106, אבל יש פער בנתוני השכר. האומדן הקודם אינו עדכני. צריך לבקש ממחלקת השכר הסבר או טופס מתוקן. אין צורך בחיבור לתיבת הדואר כדי להמשיך.”
- Russian: “Я прочитал сохранённое дело. Форма טופס 106 получена, но данные о зарплате расходятся. Предыдущую оценку нельзя считать актуальной. Попросите расчётный отдел объяснить расхождение или выдать исправленную форму. Для продолжения подключение почты не требуется.”
- Arabic: “قرأتُ ملفك المحفوظ. وصل نموذج טופס 106، لكن بيانات الأجر متعارضة. لا يمكن عرض التقدير السابق بوصفه تقديراً حالياً. اطلب من قسم الرواتب توضيح الفرق أو إصدار نموذج مصحح. يمكننا المتابعة دون اتصال بالبريد.”

For manual refund-service entry include להגשת הבקשה in the actual reply with its translation: Russian “Подать заявление”, Arabic “تقديم الطلب”. Explain that this is only the public entry described by the [official service source](portal-and-routing.md), even when no portal action is possible. If the route remains unresolved, explicitly defer submission pending route/evidence review. For coordination keep לעריכת תיאום מס beside the translation. Do not invent a label within an authenticated page.

Actual independent Russian/Arabic trials and their observed responses are recorded in the development verification report only after execution. Text examples or Python language-code assertions do not pass acceptance9 by themselves.
